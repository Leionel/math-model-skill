## 2. R7：最终图基础探针与两处证据缺口

### 2.1 空白/裁切像素探针

`scripts/figures/check_figure.py` 新增 `rendered_png_checks`：先把 RGBA 按透明度合成到白底，再以灰度中位数估计背景，`|gray − background| > 0.02` 判内容像素；

- **空白画布**（无内容像素）→ 阻断性 error；
- **内容触碰画布边缘**（被裁切）→ 阻断性 error，提示导出前加边距；
- numpy/matplotlib 缺失或 PNG 解码失败 → 降级为 warning（`ImportError` 守卫源于历史上真实发生过的缺 numpy 环境失败，不是臆想防御）。

已知边界：像素探针只检测近空白和边界接触；中位数背景估计在内容占画布 ≥50% 时也可能反转。报告 `automated.rendered` 字段同步进 `schemas/figure_qa.schema.json`（`checked/content_bbox/coverage`）。Draw.io 的框几何由下一节单独检查。

回归覆盖干净图、越界图、空白图与“透明像素携带随机 RGB”图；后者必须仍判空白。

### 2.2 GAP-05：正文插图与证据链的哈希绑定

`scripts/qa/check_consistency.py`：

- 收集正文 `\includegraphics` 引用的图片路径（按源 tex 目录解析相对路径，含扩展名探测 `.png/.pdf/.jpg/.jpeg/.eps/.svg`）；
- 与 `artifact_dag` 登记的 sha256（节点 `path+sha256` 与 `outputs[]` 两种形态都查）比对；
- **摘要不一致 → 阻断性 error**（可拦住"注册后偷换位图"）；未登记 digest → warning（`--strict` 下升级为失败）；
- `\input` 与 `\includegraphics` 解析不得越出项目根；多个同后缀候选若登记了不同摘要，按歧义阻断，不任选其一；
- 顺手修了一个潜在旧缺陷：逐图"声明了渲染产物但正文未出现"的警告原来拿**全局**登记集合比较、永远不触发，现改为与该图自身候选比较。

### 2.3 GAP-13：图题数字与正文/冻结结果对账

图题（caption）中的整数、小数、千分位、科学计数法和百分数必须出现在 frozen/derived result 的 `display_value/value` 中；仅在正文重复同一数字不能把它变成证据。示意性图题（含"示意/illustrative/schematic/非精确/不承载"）豁免。失配为 warning，`--strict` 下阻断。

回归：`test_figure_binding.py` 8 项，覆盖 digest 匹配、偷换字节、缺 digest 的严格度差异、图题数字证据对账，以及越界路径和歧义候选等边界。

### 2.4 Draw.io 原生几何 QA 与 Figure Reference Cards

`scripts/figures/check_diagram_spec.py` 现在读取 native `mxGeometry`，要求 spec 中每个节点唯一映射到 `harness-node`，并阻断：

- `DRAWIO_NODE_COLLISION`：两个声明节点有正面积重叠；
- `DRAWIO_OUT_OF_BOUNDS`：节点越出 `pageWidth/pageHeight`；
- `DRAWIO_FONT_SIZE`：节点字号低于 spec 声明下限；
- `DRAWIO_READING_ORDER`：主边违背 `left_to_right` / `top_to_bottom`；
- `DRAWIO_NODE_MAPPING`：缺失、重复或多出的 tagged node。

这些检查针对可确定的 Draw.io 框几何，不把 PPTX/最终 PDF 的文字拥挤、视觉层级和审美冒充为机器可判事实；后者继续走 final-size 与人工视觉复核。

6 张 Figure Reference Cards 新增与路由一致的 `semantic_type`。`select_reference_cards.py` 支持 `--semantic-type`，`tool_router.py` 对 data、PPTX 与 Draw.io 路由均返回 `figure_reference_cards`。选择链仍是 `claim/evidence → semantic_type/evidence_role/data_shape → card`；卡片不是当前题 evidence，也不复制来源图。

## 3. R8：作者层、派生层与契约消费闭环

R8 建议 1–3 在当前工作树已有实际落点，而不是延期设计：

1. `human_surface.py` 用 `00_PROJECT_BRIEF.md`、研究/模型/求解报告、Paper Director Plan、section/figure brief 作为非覆盖作者面；仅在机器消费者需要时，从显式 fenced YAML 编译 schema-valid IR，避免平行手写 JSON。
2. `harness init` 只在文件缺失时生成带任务解释、填写顺序和可选 machine-source block 的最小作者模板；空 block 不能编译，防止占位内容成为合同。
3. `harness setup --stage`、`status.failures_summary` 与 `prepare M1/W1/W2/S1` 只投影当前阶段的能力、阻断与待审信息；投影含源 hash，且不能通过编辑 Markdown 改 Gate。

`scripts/qa/audit_contract_consumption.py` 使用 `textual_schema_filename_reference` 方法：对 `schemas/*.schema.json` 逐一扫描 `scripts/**` 与 `tests/**` 是否出现 schema 文件名，产出静态引用清单、Gate surface 是否出现该名称、是否无引用/仅测试引用。

**边界：** 这不是调用图或运行期覆盖率；`gate_surface_referenced=true` 不能证明该分支在真实 Gate 中被执行。报告保留旧字段 `gate_wired` 仅为兼容，其语义也是“Gate surface 文本引用”。

**当前真实审计结果（31 个 schema）：** `--strict` 为 PASS，0 orphan、0 test-only；19 个被 Gate surface 文本引用。此前三个低消费 schema 已闭环：

| Schema | 发现 | 处置 |
|---|---|---|
| `figure_qa.schema.json` | 孤儿：生产者 `check_figure.py` 从不自校验 | **已修复**：写入报告后按 schema 自校验；同时把生产者实际写出的 `final_size_review` 补进 schema（这正是"契约与代码漂移"的实锤案例） |
| `command_receipt.schema.json` | 仅测试强制 | `run_and_record.py` 在首次落盘前校验 v1/v2 producer 输出 |
| `submission_receipt.schema.json` | 无消费者 | 新增 `check_submission_receipt.py` 与 `harness submit receipt`，重算 hash、F1 成员身份、官方端点和 accepted 状态 |
| `validation_report.schema.json` | 重算但不校验结构 | `evaluate_obligations.py` 在首次落盘前做 schema 校验；freeze 仍以独立重算防手改 |

回归：`test_contract_consumption.py` 4 项（真实仓库全覆盖、figure_qa 已有运行期消费者、合成仓库中孤儿/仅测试被标记、`--strict` 下失败）。

**边界（如实记录）：** 静态 schema 引用不能证明真实 Gate 分支运行，也不能证明每个字段有足够的业务价值；producer schema 校验只证明结构，不能替代收据真实性或 validation recomputation。R8 的结构实现已完成，但“从 init 到 M1 的手填字段数显著下降”仍需 R1 真实题记录用时/字段数，当前不把回归测试冒充赛时效益。

## 5. R10：可分发包（最小片，实际交付超出原最小片）

原计划最小片只做"资源完整性校验"；实际做到了**真实可安装且通过完整性校验的 wheel**：

1. **事实起点：** 构建前的 wheel 只有 107 个 `scripts/` 条目，`schemas/ references/ assets/ competition_profiles/` 全部为 0 —— 装上即用不了契约与参考件。
2. **`pyproject.toml` 修复：** 资源目录以 namespace package 纳入打包，`package-data` 覆盖全部资源扩展名（`.json/.md/.yaml/.png/.pdf/.drawio/.svg/.pptx/.tex/.mplstyle`）。
3. **`scripts/qa/check_package_resources.py`**：checkout 模式验证四个资源根非空；`--wheel` 模式逐一核对磁盘资源文件是否全部出现在 wheel 归档内（`.gitkeep` 占位符按规则排除，setuptools 也不收点文件，两边一致）。**不以 `pip install .` 成功冒充完整性验证**——这是两条独立检查。
4. **真实验证：** 2026-08-29 重建的 wheel 有 429 条目（schemas 31 / references 181 / assets 98 / competition_profiles 5 / scripts 109）；`check_package_resources.py --wheel` 返回 `ok: true`、0 errors、0 warnings，磁盘侧除 `.gitkeep` 外无缺失。安装到临时目录后的 `harness --help` 与 31 个 schema 邻接审计沿用前次验证结果。

回归：`test_package_resources.py` 4 项，覆盖真实仓库资源根、合成完整 wheel、缺资源阻断与归档映射。

已知权衡：资源目录以顶层 namespace package 形式进 wheel，`references/assets/schemas` 会出现在安装环境的顶层导入命名空间（名称偏通用）。若未来出现冲突，应改为专用资源包名；当前无冲突证据，不改。
