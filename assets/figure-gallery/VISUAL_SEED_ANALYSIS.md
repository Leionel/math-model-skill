# Visual Seed Analysis

This is a composition study of the checked-in reference-only assets, not an
evaluation of their domain claims.

## Research Framework

### Reading order

The contact sheet's research framework reads left to right from input data to
representation, then a clearly enclosed core model, output list, and result.
A low-contrast dotted feedback rail returns from result to input without
competing with the primary chain.

### Visual hierarchy

The title is compact; the largest visual weight belongs to the central model
container and the result card. The primary sequence uses solid dark arrows;
supporting relations use light dotted arrows.

### Core block and secondary blocks

The core is one grouped card with its own internal stack. Input, representations
and output are lightweight cards, so the reader can distinguish processing from
context in one scan.

### Edge style, colour and density

Use one dark primary-flow stroke, one subdued feedback style, and a small
semantic palette. Density is modest: there is no attempt to put every
implementation detail inside the overview.

### What to borrow / not to copy

Borrow the primary-versus-feedback contrast, central grouping, and concise
labels. Do not copy the named layers, NLP-specific topology, icons, or text.

## Model Pipeline

The pipeline seed makes stages legible with a single left-to-right rail and
numbered headers. It reserves lower panels for concrete evidence (example,
matrix, gauge) rather than putting those details in the main path. This is a
good pattern for a mathematical-modeling workflow: show data → model →
validation → result on the rail, and place only decision-critical diagnostics
below it. Avoid importing its AI-product terminology or treating decorative
gauges as numerical proof.

## ContextForge

The comparison image demonstrates a dense framework that remains navigable:
a focal composer sits in the centre, source panels surround it, a numbered
resolution flow controls the left, quality gates live on the upper right, and
the trace package ends the reading path. The teal/blue/orange/red palette has
stable semantic roles, while dashed lines mark feedback rather than another
main route. Borrow bounded panels, a dominant centre, and explicit feedback;
do not copy the source-system taxonomy or create an equally dense diagram for
a simple two-step model.

## SkillCircuit

The module QA contact sheet makes the production method visible: construct and
inspect modules separately, then integrate. Paired reference/recreation
examples reveal whether labels, hierarchy and edge direction survive the
editable Draw.io version. For a large math-modeling framework, use this to
split a main overview, a sub-model, and a validation module before composing
the final figure. Do not use every module merely to make a small diagram look
more sophisticated.

## Local-gallery rules

Every new local example must name a primary and optional secondary reference,
state what it borrows, state what it refuses to copy, and keep a `brief.md`,
editable source, vector export and final-size preview together. The gallery is
for visual grammar; the project's own brief and evidence remain authoritative.
