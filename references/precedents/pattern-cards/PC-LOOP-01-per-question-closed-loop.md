# 子问题论证闭环

- **card_id**: PC-LOOP-01
- **problem_family**: 全题型
- **trigger**: 开始撰写任何一个子问题的章节时；尤其当各问章节结构开始漂移、缺少统一骨架时。
- **mechanism**: 每个决定性子问题都要让读者找到四类信息：为什么这样建模、数学对象如何定义、怎样求解、结果如何被验证。它们可以分成多个小节，也可以在短问题中紧凑合并；章节结构服从推导依赖，不强制复用四个标题。算法只报告影响可复现性的设置，图表只在承担证据角色时出现。
- **dependency_shape**: 依赖子任务分解和 Model Contract；对下游提供完整的 claim→model→execution→validation 闭环，而不是固定版式。
- **validation_signature**: 每个关键 claim 落实与模型类型相称的验证义务；优化、预测、仿真等题型采用各自合适的基线、留出或诊断证据。
- **rhetorical_moves**: 动机→定义/推导→实现与求解→结果证据→边界；可按依赖关系交错或合并。
- **failure_modes**: 直接堆公式而不解释对象；只报结果不给可复现求解信息；结论没有相称验证；机械套四段导致重复和章节漂移。
- **do_not_copy**: 不复制任何一届的四段标题文字与段内固定句式；不把某届的算法步骤模板（步长、迭代数）当结构照搬。
