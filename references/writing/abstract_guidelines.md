# 数学建模论文摘要写作规范（Skill Reference）

## Purpose

本规范用于约束数学建模论文摘要的生成、改写与自检。目标不是把摘要写成“引言缩写版”，而是把摘要写成一段**可独立阅读、可快速判断论文质量的微型论文**。

该规范提炼自一篇围绕国赛一等奖论文摘要的经验性总结，并已重写为适合 Agent/Skill 直接调用的执行规则。

---

## When to Apply

当任务包含以下任一情形时，必须读取本规范：

- 撰写数学建模论文摘要
- 对已有摘要进行润色、压缩或重构
- 对 AI 生成摘要做去模板化和质量检查
- 从正文反推摘要
- 对摘要进行评分、批改、指出失分点

---

## Core Principle

### 1. 摘要不是引言，而是独立的小论文

摘要的作用不是“把读者引到正文里”，而是让评审仅通过摘要就能基本判断：

- 你解决了什么问题；
- 你用了什么模型和方法；
- 你得到了什么结果；
- 结果是否像样。

因此，摘要中的每一句话都应该陈述**已经完成的工作**，而不是未来计划。

### 2. 评审最想看到的是“做了什么 + 怎么做 + 得到了什么”

摘要必须压缩展示完整工作闭环，而不是只讲背景、动机和空泛结论。

---

## Standard Structure

## 一、动态的“总—分—总”结构

建议采用“总起 + 按子问题分述 + 收束 + 关键词”的结构；段落数量跟随题目子问题和篇幅要求，不固定为四段。

### 第 1 段：总起句（一句话定乾坤）

第一句必须开门见山，直接交代问题、模型、方法、目标。

推荐句式：

> 本文针对 XX 问题，建立了 XX 模型，采用 XX 方法进行求解，得到了 XX 结果。

要求：

- 不要绕背景；
- 不要先讲问题重要性；
- 不要写成“本文将……”“我们打算……”“接下来会……”。

### 中间若干段：按问题顺序分述

对每一个问题，按顺序描述，且每个问题都必须尽量包含以下三个要素：

1. **做了什么**：建立了什么模型；
2. **怎么做的**：用了什么方法、算法或关键思路；
3. **得到了什么**：给出核心结果，优先给出具体数值。

模板可写为：

> 针对问题一，建立了 XX 模型；采用 XX 方法 / 算法求解；得到 XX 结果，其中关键指标为 XX。

进一步要求：

- 各问题最好体现递进关系，而不是四个彼此割裂的小题；
- 第一问可以写得稍详细，后续问题可适度简略；
- 即便后续问题简写，**模型、方法、结果**三要素仍尽量保留；
- 如果某问在前一问基础上改进，应明确点出这一关系。

### 最后一句：简短收束

结尾可以用一句话完成收束，例如：

- 对模型进行了灵敏度分析与稳健性检验，结果表明模型具有较好的可靠性；
- 所建模型可推广应用于 XX 类问题。

要求：

- 只写一句即可；
- 不要展开成长篇结论段；
- 若正文并未做相关分析，不要虚写。

### 关键词

关键词建议 3–5 个，遵循“问题领域 + 核心模型 + 核心算法”的顺序。

例如：

- 定日镜场
- 单目标优化
- 遗传算法
- 蒙特卡洛方法

避免使用过泛词：

- 数学建模
- 优化
- 算法
- 大学生竞赛

## Writing Rules

## 二、用词规范

### 1. 优先使用客观、标准、低修辞的学术表达

高频安全词：

- 建立
- 针对
- 采用
- 得到
- 基于

示例：

- “建立了 XX 模型” 优于 “构建了 / 开发了 / 设计了 XX 模型”；
- “采用 XX 算法求解” 优于 “使用了 / 运用了 XX 算法”；
- “得到 XX 结果” 优于 “获得了 / 求解出了 XX 结果”。

### 2. 少用自我评价和夸张修辞

避免：

- 创新性地提出了……
- 结果非常准确……
- 模型具有很强的鲁棒性……
- 具有重大理论意义……
- 填补了空白……

更好的写法是用事实代替形容词，例如：

- 不说“结果很准确”，改为“误差小于 5%”；
- 不说“模型很创新”，改为“在 XX 模型基础上引入了 XX 机制”。

### 3. 时态必须统一为完成态 / 已完成叙述

避免：

- 本文将……
- 我们打算……
- 接下来会……

改为：

- 本文建立了……
- 采用了……
- 得到了……

## Numbers and Results

## 三、结果与数字的放置规则

摘要中的关键结果必须列入 `paper_plan.abstract_result_ids`，并能沿 `evidence_registry → frozen_results` 回溯。不要从聊天上下文或手工笔记复制数字。

### 1. 摘要必须尽量给出具体结果

如果摘要没有任何具体结果，只写：

- 建立了模型；
- 设计了算法；
- 结果表明模型有效；

那么信息量通常不足，可信度也会明显下降。

### 2. 只放能够支撑核心结论的冻结数字

数量由题目要求和论证需要决定，不按“每问 2–4 个”硬编码。不要把所有结果都堆进摘要，优先保留：

- 最优目标函数值；
- 关键决策变量；
- 预测误差；
- 综合评分 / 排名；
- 最重要的方案指标。

### 3. 数字必须满足三项基本要求

#### (1) 有效数字统一

全文及摘要中，有效数字风格应保持一致，例如：

- 要么统一保留整数；
- 要么统一保留 2 位小数；
- 要么统一保留 4 位小数。

不要出现：

- 0.5888
- 60MW
- 3.1415926

这种混乱并列的情况。

#### (2) 单位不能漏

数字后必须尽量跟单位，例如：

- 36.99 MW
- 0.5888 kW/m²
- 125936 m

没有单位的工程类结果往往意义不明。

#### (3) 单位制应统一

不要混用：

- 米 / 英尺；
- 千瓦 / 兆瓦；
- 小时 / 分钟（若无说明）。

### 4. 如果结果太多，只保留决定性结果

把次要结果留在正文表格或附录。摘要应独立可读，不引用 `result2.xlsx` 等内部工程文件名，也不靠“详见某文件”代替结论。

## Common Failure Modes

## 四、最容易丢分的 10 个摘要雷区

### 1. 写成工作计划

典型错误：

- 本文将研究……
- 我们要……
- 接下来会……

### 2. 没有具体结果

通篇只有“建立了模型、结果有效”，没有数字支撑。

### 3. 背景铺垫过长

开头半页都在讲问题重要性，迟迟不进入正题。

### 4. 摘要里出现公式和参考文献

摘要通常不应放公式，不应写“正如文献 [3] 指出……”。

### 5. 四个问题平均用力，像流水账

没有重点，所有问题篇幅完全一样，读者看不出亮点。

### 6. 自吹自擂

频繁出现“首次提出”“填补空白”“重大意义”等夸饰表达。

### 7. 逻辑不清

看完摘要仍不知道：

- 哪个问题用了哪个模型；
- 哪个方法对应哪个问题；
- 哪个结果回答了哪个任务。

### 8. 太长或太短

优先遵守竞赛模板的字数与版面要求。模板没有规定时，可把 300–500 字作为经验区间，而不是硬 Gate。

### 9. 关键词太泛

“数学建模”“优化”“算法”一类词区分度太低。

### 10. 最后不检查

常见问题包括：

- 错别字；
- 病句；
- 数字与正文对不上；
- 单位缺失；
- 逻辑矛盾。

## Revision Workflow

## 五、推荐改写流程

摘要不要一遍写完就提交。建议至少经历以下修订步骤：

1. **初稿**：正文基本完成后，根据正文写出摘要初稿；
2. **结构调整**：整理为四段式，保证问题顺序清晰；
3. **用词收束**：删掉空话、套话、夸张表达；
4. **数字校对**：逐个核对数值、单位、有效数字；
5. **通读润色**：连续读 2–3 遍，检查是否顺畅、是否像“独立小论文”。

## Execution Rules for Agent

## 六、Agent 执行时的 MUST / SHOULD / AVOID

### MUST

- 必须把摘要写成已完成工作的总结；
- 必须在第一句中说明问题、模型、方法；
- 必须尽量给出具体结果，尤其是关键数字；
- 必须按问题顺序组织内容；
- 必须保证数字、单位、有效数字风格一致；
- 必须使用具体关键词；
- 必须在最终输出前进行通读和自检。

### SHOULD

- 应优先保留能够直接支持核心结论的少量冻结结果；
- 应体现问题之间的递进关系；
- 应使用“建立 / 针对 / 采用 / 得到 / 基于”等稳健表达；
- 应把最有分量的问题写得略详细一些；
- 应在结尾用一句话补充稳健性、推广性或适用性。

### AVOID

- 避免把摘要写成引言；
- 避免长背景、长动机、长意义；
- 避免未来时、计划式表达；
- 避免无数字的空结论；
- 避免堆砌形容词；
- 避免公式、参考文献；
- 避免关键词泛化；
- 避免摘要与正文数字不一致。

---

## Final Checklist

## 七、最终检查清单

提交摘要前，至少逐项检查：

- [ ] 第一话是否开门见山说明了问题、模型、方法？
- [ ] 摘要是否全部在陈述已经完成的工作？
- [ ] 每个问题是否都尽量包含“做了什么 / 怎么做 / 得到了什么”？
- [ ] 是否给出了最关键的具体结果，而不只是“模型有效”？
- [ ] 数字是否附带必要单位？
- [ ] 有效数字和单位制是否统一？
- [ ] 各问题是否按题目顺序写出，并保持逻辑递进？
- [ ] 是否删去了空泛背景、夸张修辞和自我吹捧？
- [ ] 是否没有公式、参考文献和无用关键词？
- [ ] 是否通读至少两遍，确认语句通顺且数字准确？
