# Evidence-Driven Figure Design

图的任务是压缩证据并帮助评审判断 claim，不是装饰论文或完成图数配额。正式图的数量由 requirement → claim → evidence coverage 决定。

## 先写 Figure Contract

画图前回答：

1. 图要支持哪个 `claim_id`，回答哪个子问题？
2. 使用哪些 `evidence_id` 和数据 artifact？
3. 为什么图比文字或表格更有效？
4. 每个 panel 展示什么，统计量、样本范围和不确定性如何定义？
5. caption 可以安全得出什么结论，不能外推到哪里？

这些字段写入 `paper_plan.figures[]`。探索性图不必建立完整合同；只有进入论文的正式图才需要。

对于总览图、任务流程图和模型框架图，再执行 [Diagram Workflow](diagram_workflow.md)：先写结构化图稿和唯一 message，再在可编辑矢量工具中排版。这里的“矢量优先”不排斥位图兼容输出；位图必须是显式 `raster_only` 例外，并保留源文件、DPI 和人工复核记录。

## 按证据关系选图

| 论证任务 | 优先形式 | 必查项 |
|---|---|---|
| 时间变化/预测 | 折线、区间带、残差图 | 时间轴、训练/测试边界、不确定性 |
| 方案比较 | 点图、条形图、small multiples | 基线、共同尺度、误差或区间 |
| 分布与异常 | 直方/密度、箱线/小提琴、ECDF | 样本量、异常值处理、统计定义 |
| 变量关系 | 散点、拟合线、残差/偏依赖 | 相关不等于因果、过绘制、置信区间 |
| 参数/敏感性 | 热力图、等高线、tornado、响应曲线 | 变化范围、固定条件、稳定区间 |
| 空间结构 | 地图、网格、分区图 | CRS、比例尺、图例、空间分辨率 |
| 网络/路径 | 网络图、流图、路径高亮 | 节点/边含义、布局是否误导 |
| 模型流程 | 简洁流程图或框架图 | 与实际代码一致，不把概念图伪装成数据证据 |

3D 图只有在第三维确实承载信息且不会遮挡时才使用。

## 设计优先级

1. **准确**：数据、变换、统计定义、单位和边界正确。
2. **必要**：删除后 claim 会明显更难判断。
3. **可读**：论文实际尺寸下标题、轴、图例、panel label 可辨认。
4. **一致**：术语、符号、颜色语义和正文一致。
5. **克制**：避免默认模板堆叠、无意义渐变、阴影、装饰 3D 和过密标注。

优先使用位置和长度表达重要数值；颜色用于分组或辅助编码。对色觉缺陷友好，并保证灰度打印时仍可区分关键组。

## Evidence Coverage 决策

对每个必要 claim 依次判断：

1. 文字能否清楚表达？能则不画。
2. 精确查数是否更重要？是则用表。
3. 是否需要比较趋势、结构、分布或不确定性？是则建立 Figure Contract。
4. 多张图是否表达同一关系？优先合并为 small multiples、主图 + inset 或共享坐标的 panel。

不要规定“至少 8 张”“每类 3 张”，也不要默认每篇都需要技术路线图、敏感性图和模型框架图。

## QA

### 可程序化检查

- figure/claim/evidence ID 是否存在；
- 数据与源文件是否存在且哈希一致；
- panel map、统计定义、paper location 和 caption claim 是否齐全；
- LaTeX 图片路径、label/ref 是否有效；
- 数字、单位和术语是否与 registry/plan 一致。

### 必须人工检查

- 图是否真的支持 claim，而非装饰；
- 论文最终尺寸下是否可读，有无裁切、字体替换或 panel 失衡；
- caption 是否准确描述统计量和边界；
- 是否存在视觉夸大、选择性展示或被隐藏的失败结果。

当前 P0 不声称自动完成 Nature Figure 的源码预检、导出 PDF 字体/裁切和逐 panel 最终尺寸审查；这些属于 P1，S1 仍需最终渲染人工确认。
