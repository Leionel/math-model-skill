# 数学建模论文可视化设计规范

> 用途：作为数学建模 / 科研写作类 Skill 的可视化子模块，用于指导 Agent 生成、审查和优化论文中的图表、流程图、模型框架图与结果展示。

## 1. 核心原则

数学建模论文中的图不应只是“把数据画出来”，而应服务于完整的建模逻辑：

```text
问题理解 → 机理分析 → 模型建立 → 算法求解 → 结果展示 → 验证与解释
```

生成或优化图表时，优先遵循以下原则：

1. **信息密度优先于图表数量**：避免将可以整合的信息拆成大量单一柱状图、折线图。
2. **模型表达优先于装饰性可视化**：除结果图外，应主动考虑问题机理图、技术路线图、模型框架图和算法流程图。
3. **一张图回答一个完整问题**：每幅图应对应明确的分析目标，而不是“有数据就画图”。
4. **图表必须服务论证**：正文中应能解释“为什么画这张图、它说明了什么、它支持了哪个结论”。
5. **避免模板化 AI 痕迹**：默认 matplotlib 风格、重复柱状图、机械式配色和大量低信息密度图片应尽量减少。

---

## 2. 图表类型选择规则

### 2.1 数据结果图

当需要展示数值结果时，不要默认使用柱状图或折线图，应根据分析任务选择图形。

| 分析目标 | 优先考虑 |
|---|---|
| 时间趋势 | 折线图、置信带、局部放大图 |
| 多方案比较 | 分组柱状图、点图、排序图 |
| 多指标综合比较 | 热力图、平行坐标图、谨慎使用雷达图 |
| 空间分布 | 地图、空间热力图、轨迹图 |
| 参数敏感性 | 响应曲线、敏感性热力图、龙卷风图 |
| 模型误差 | 残差图、误差分布图、QQ 图 |
| 分类或聚类 | 降维散点图、聚类热图 |
| 网络关系 | 网络图、桑基图 |
| 多目标优化 | Pareto 前沿图 |
| 不确定性 | 误差棒、置信区间、分布图 |

### 2.2 结构与逻辑图

对于数学建模论文，Agent 应主动判断是否需要以下非数据图：

#### 问题机理图

用于说明现实系统中的对象、变量和因果关系。

适用场景：

- 变量之间存在明显作用关系；
- 题目包含多个主体或多个阶段；
- 单靠文字难以快速说明问题结构。

#### 模型框架图

用于说明各子模型、算法模块之间的调用关系。

适用场景：

- 一个问题拆成多个子问题；
- 多模型组合；
- 数据预处理、预测、优化、评价之间存在链式关系。

#### 技术路线图

用于给出整篇论文的总体解决流程。

推荐结构：

```text
数据获取
  ↓
预处理与特征构造
  ↓
问题分析
  ↓
模型建立
  ↓
算法求解
  ↓
结果验证
  ↓
敏感性 / 稳健性分析
  ↓
结论与建议
```

#### 算法流程图

当存在迭代、搜索、优化、启发式算法或多阶段求解流程时，优先使用流程图，而不是纯文字描述。

## 3. 需要避免的常见问题

### 3.1 低信息密度

以下情况通常需要合并或重构：

- 一个指标对应一张图，连续出现多张结构完全相同的图；
- 多个方案分别绘制成独立柱状图；
- 同一组数据只是更换颜色或排序后重复出现；
- 图中只有 3–5 个数据点，却占据大量版面。

优先尝试：

- 共用坐标轴；
- small multiples；
- 主图 + inset；
- 组合图；
- 热力图；
- 归一化后统一比较。

### 3.2 图表与建模逻辑脱节

如果一张图无法回答以下至少一个问题，则应重新考虑是否保留：

- 它解释了什么现象？
- 它支持了哪个模型假设？
- 它证明了模型有效吗？
- 它比较了哪些方案？
- 它揭示了什么规律？
- 它支撑了哪个最终结论？

### 3.3 默认模板感过强

应避免：

- 大量默认蓝色 matplotlib 图；
- 相同字号、相同排版、相同图例位置机械重复；
- 标题直接写成代码变量名；
- 横纵轴缺少量纲；
- 图例内容与正文术语不一致；
- 3D 图仅用于视觉效果，没有额外信息价值。

## 4. 高质量图表生成流程

Agent 在生成图表前，应依次执行：

### Step 1：明确图的任务

用一句话回答：

> 这张图要让阅卷者在 5–10 秒内看懂什么？

### Step 2：确定变量关系

确认：

- 横轴是什么；
- 纵轴是什么；
- 是否有分组变量；
- 是否需要表达不确定性；
- 是否存在时间、空间或网络结构。

### Step 3：选择最合适的视觉编码

优先顺序通常为：

```text
位置 > 长度 > 角度/面积 > 颜色深浅 > 颜色类别
```

重要的数值比较尽量通过位置和长度表达，而不是仅依赖颜色。

### Step 4：控制单图复杂度

一张图应信息充分，但不能同时塞入过多变量。

若信息过多，应拆为：

- 主结果图；
- 敏感性图；
- 补充材料图。

### Step 5：与正文建立对应关系

正文中应至少包含：

```text
如图 X 所示，……
这说明……
因此……
```

图不能独立存在，也不要在正文中重复逐项念图中数据。

---

## 5. 用 evidence coverage 决定图表配置

不要预设技术路线图、主结果图或敏感性图的数量。按以下顺序决定是否需要正式图：

1. 从题目 requirement 找出必须回答的 claim；
2. 判断文字或表格能否清晰承载 evidence；
3. 只有图形具有不可替代的比较、结构或不确定性表达价值时，才建立 Figure Contract；
4. 将次要、重复、参数遍历和调试图留在附录或直接删除。

技术路线图、模型框架图、误差图和敏感性图都是候选类型，不是每篇论文的固定配额。

---

## 6. Agent 自动检查清单

在论文输出前，逐项检查：

### 内容层面

- [ ] 每张图是否对应一个明确分析问题？
- [ ] 是否存在可以合并的重复图？
- [ ] 是否缺少模型框架图或技术路线图？
- [ ] 是否有关键结论只靠文字，没有图形支持？
- [ ] 是否对模型误差、稳定性或敏感性进行了可视化？

### 信息表达

- [ ] 横纵轴是否有名称与单位？
- [ ] 图例是否清楚？
- [ ] 标题是否表达图的结论或用途，而非简单变量名？
- [ ] 字号在论文缩放后是否仍清晰？
- [ ] 是否避免使用无意义的 3D 效果？

### AI 痕迹检查

- [ ] 是否连续出现大量默认柱状图或折线图？
- [ ] 是否所有图都采用完全相同的模板？
- [ ] 是否存在“为了有图而画图”的内容？
- [ ] 是否可以通过组合图提高单图信息密度？
- [ ] 图形是否体现了对模型本身的理解？

---

## 7. 对 Agent 的执行指令

当用户要求“生成数学建模论文”“优化数模论文”“画图”“美化结果图”时：

1. 不要直接批量生成柱状图和折线图。
2. 先判断论文逻辑链，并给出推荐图表清单。
3. 优先保留高信息密度图。
4. 至少检查是否需要技术路线图、模型框架图或算法流程图。
5. 生成结果图后，说明每张图对应的分析目的。
6. 如果多张图表达相近内容，主动建议合并。
7. 对正式竞赛论文，图形风格应统一，但不能机械模板化。
8. 不得仅为了“降低 AI 痕迹”而进行无意义装饰；核心仍是信息表达和建模逻辑。

---

## 8. 使用边界

“AI 风格图表会被直接降档”属于经验性观点，不应视为正式竞赛评分规则。

本模块的目标不是隐藏 AI 使用，而是避免：

- 模板化输出；
- 低信息密度；
- 图表与模型脱节；
- 缺少真正体现建模思路的可视化。

最终评价标准仍应是：**图是否准确、必要、清晰，并有效支撑模型与结论。**
