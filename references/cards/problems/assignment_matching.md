# Problem Pattern Card: Assignment & Matching (指派与匹配类)

## 1. 典型业务结构
$n$ 个任务/人员/设备分配给 $m$ 个对象/岗位/工作台，代价或收益矩阵 $C=[c_{ij}]$ 已知，要求一对一（或多对一）指派使总代价最小/总收益最大：人员排班、任务-机器指派、传感器-目标配对、相亲/组队匹配。CUMCM 常作为子问题出现在调度与分配大题中。

## 2. 常见比赛翻车陷阱
- **人数≠任务数未处理**：不平衡指派直接套匈牙利算法报错或得非满秩解（须加哑行/哑列，哑代价取 0 或大 M 并说明方向）；
- **最大化问题忘记取负**：匈牙利算法标准形式是最小化，$\max \sum c_{ij}x_{ij}$ 必须转换为 $\min \sum (-c_{ij})x_{ij}$；
- **"多对一"误建成一对一**：一个岗位能接多个任务时是运输/二部图流问题，不是标准指派；
- **整数性冗余担忧**：指派 LP 的约束矩阵全单模（TU），线性求解自动得 0-1 解，无需手动加整型约束把求解器拖慢；
- **哑元结果未剔除**：把哑任务/哑岗位的"分配结果"写进论文结论。

## 3. 标准推荐实战流水线
1. **形式化**：标准指派 $x_{ij}\in\{0,1\}$，$\sum_j x_{ij}=1\ \forall i$，$\sum_i x_{ij}=1\ \forall j$，$\min \sum c_{ij}x_{ij}$；不平衡时补哑元；
2. **求解**：小规模用匈牙利算法（$O(n^3)$）验证；通用建 MILP/网络流（scipy `linear_sum_assignment` 即匈牙利实现）；
3. **扩展**：带容量上限 → 运输问题/最小费用流；带互斥或先后约束 → MILP 加逻辑约束（Big-M 紧界见 failures/unrealistic_big_m）；
4. **验证**：所有行/列度和恰为 1（哑元除外）；与贪心 Baseline（每行取最小代价，冲突后贪心修补）对比；
5. **敏感性**：代价矩阵元素 ±10% 扰动下最优指派结构是否稳定（哪些配对是"铁配"、哪些是临界的）。

## 4. 论文逻辑组织建议 (CEEL 范式)
- **表/图 1**：代价矩阵热图 + 最优指派连线图（哑元单独标注）；
- **图 2**：代价扰动下指派保持率/翻转配对清单；
- **论证段落**：Claim（最优指派总代价）→ 与 Baseline 差值 → 结构解释（为什么这些配对稳定）→ 边界（代价估计误差大于临界差值时指派会翻转）。
